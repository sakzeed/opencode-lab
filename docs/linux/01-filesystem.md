# บทที่ 1: ระบบไฟล์ และการเดินทางในระบบ

## 1.1 ระบบไฟล์คือต้นไม้เดียว

Linux ไม่มี `C:\` หรือ `D:\` — ทุกอย่างต่อจาก `/` (root) ต้นไม้เดียว อุปกรณ์ถูก "ต่อ" เข้ามาเป็นโฟลเดอร์ (`mount`) ไม่ใช่ไดรฟ์แยก

โฟลเดอร์สำคัญที่ต้องรู้:

| Path | เก็บอะไร | บนเครื่องนี้ |
|---|---|---|
| `/etc` | config ของระบบ | `os-release`, `apt/`, `passwd` |
| `/usr/bin` | โปรแกรมที่ติดตั้งจาก package | 257 ไฟล์ (`ls /usr/bin \| wc -l`) |
| `/var` | ข้อมูลที่เปลี่ยนตลอด (log, cache, DB) | `apt` cache อยู่ที่นี่ |
| `/home`, `/root` | บ้านของผู้ใช้ / ของ root | คุณอยู่ที่ `/root` |
| `/tmp` | ไฟล์ชั่วคราว | tmpfs — หายเมื่อ host เคลียร์ |
| `/proc`, `/sys` | "หน้าต่าง" มองเข้า kernel (ไม่ได้อยู่บนดิสก์) | proot bind มาจาก Android |

## 1.2 Absolute vs Relative path

```sh
pwd                  # /root            ← ตำแหน่งปัจจุบัน
cd /usr/bin          # absolute: เริ่มจาก /
cd ../etc            # relative: เทียบจากที่ปัจจุบัน → /usr/etc (ไม่มี!)
cd /var/log          # ต้องมี / นำหน้าเสมอถ้าเริ่มจาก root
cd ~                 # ~ = /root (ค่า $HOME) ไม่ใช่ /home/root
cd -                 # กลับไปโฟลเดอร์ก่อนหน้า (สลับไปมาเร็วมาก)
```

**กับดักคลาสสิก:** `cd ../etc` ให้ `/usr/etc` ไม่ใช่ `/etc` — เพราะ `..` ขึ้นไปแค่ชั้นเดียว

## 1.3 `ls` ที่ควรใช้จริง

```sh
ls -l        # long: สิทธิ์ เจ้าของ ขนาด วันที่
ls -la       # + ไฟล์ซ่อน (ขึ้นต้นด้วย .)
ls -lh       # ขนาดอ่านง่าย (K/M/G)
ls -lt       # เรียงใหม่→เก่า
ls -ltr      # เก่า→ใหม่ (ตัวท้ายสุดที่เราเพิ่งแก้) ← ใช้บ่อยที่สุด
ls -ld /tmp  # ดู "โฟลเดอร์นั้น" ไม่ใช่ "ของข้างใน"
```

อ่าน output ให้เป็น — บรรทัดจริงจากเครื่องนี้:

```
drwxr-xr-x. 2 root root 3452 Nov 14 12:42 bin
│└┬┘└┬┘└┬┘  │    │     │      │
│ │  │  │   │    │     │      └─ ชื่อ
│ │  │  │   │    │     └──────── เวลาที่แก้ล่าสุด
│ │  │  │   │    └────────────── ขนาด (byte)
│ │  │  │   └─────────────────── กลุ่ม
│ │  │  └─────────────────────── เจ้าของ
│ │  └────────────────────────── สิทธิ์ "คนอื่น" (other)
│ └───────────────────────────── สิทธิ์ "กลุ่ม" (group)
└─────────────────────────────── สิทธิ์ "เจ้าของ" (user)
  d = directory, - = ไฟล์ปกติ, l = symlink
```

## 1.4 Symlink — กลไกที่เพิ่งเจอในบทเรียน webi

```sh
ln -s go-v1.27.4 go          # symbolic link (ชี้ชื่อ)
ln go-v1.27.4/go go2         # hard link (ชี้ inode เดียวกัน — ใช้ได้เฉพาะไฟล์)
readlink -f ~/.local/opt/go  # /root/.local/opt/go-v1.27.4 ← ปลายทางจริง
```

นี่คือเหตุผลที่ `go env GOROOT` รายงาน `go-v1.27.4` ไม่ใช่ `go` — โปรแกรมถาม kernel ว่า "ตัวฉันอยู่ path จริงไหน"

## 1.5 `find` — ค้นหาที่ทรงพลังกว่า `ls`

```sh
find /etc -name "*.conf" -type f            # หาไฟล์ .conf
find ~ -maxdepth 2 -type d -name "*go*"     # หาโฟลเดอร์ชื่อมี go ลึกไม่เกิน 2 ชั้น
find /var/log -mtime -1                     # แก้ไขภายใน 24 ชม.
find . -size +100M                          # ไฟล์ใหญ่กว่า 100 MB
find . -name "*.tmp" -delete                # ⚠️ ลบจริง — ใส่ -print ก่อนเสมอ
```

## 1.6 แบบฝึกหัด (ลองเลย 3 ข้อ)

```sh
# 1) หาว่า Debian เวอร์ชันอะไร และ kernel ที่ proot หลอกไว้คืออะไร
cat /etc/debian_version; uname -r

# 2) หาไฟล์ config ใน /etc ที่ใหญ่สุด 5 อัน (ใบ้: find + du + sort)
find /etc -type f -exec du -h {} + 2>/dev/null | sort -rh | head -5

# 3) พิสูจน์ว่า symlink กับไฟล์จริงไม่เหมือนกัน
ls -l ~/.local/opt/          # go เป็น l (link)
stat ~/.local/opt/go         # ดู inode
stat ~/.local/opt/go-v1.27.4 # inode ต่างกัน
```
