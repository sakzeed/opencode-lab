# Docs Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** เผยแพร่บทเรียน 11 บทเป็นเว็บ docs ภาษาไทยบน GitHub Pages ที่ deploy อัตโนมัติเมื่อ push

**Architecture:** MkDocs Material อ่าน Markdown จาก `docs/` แล้ว GitHub Actions build เป็น static site และ deploy ผ่าน Pages artifact ไม่มี runtime server

**Tech Stack:** MkDocs Material 9.x, Python 3.12 (CI), GitHub Actions (`upload-pages-artifact` + `deploy-pages`), `gh` CLI

**Spec:** `specs/2026-11-14-docs-site-design.md`

## Global Constraints

- เนื้อหาต้นฉบับมาจาก `opencode session export ses_e25ed55bdffeKk1UODr0B0O8YI` เท่านั้น ห้ามแต่งเนื้อหาใหม่
- 1 ไฟล์ = 1 บท, มี H1 เดียว, ชื่อไฟล์เป็นภาษาอังกฤษ (URL สะอาด)
- ทุกหน้าใน `nav` ต้องมีไฟล์จริง — `mkdocs build --strict` ต้องผ่าน
- repo ต้องเป็น public ก่อนเปิด Pages (แผนฟรี)
- ห้าม commit secret: `service.json`, `*.db`, `.env`, `site/`
- commit message แบบ conventional (`feat:`, `docs:`, `ci:`, `chore:`)

## Review Focus

- ข้อความแชทหลงเข้า docs (เช่น "มีครับ 👍", "บอกได้เลยครับ") — ต้องถูกตัดก่อน commit
- code fence ที่มี `#` อยู่ข้างในต้องไม่ถูกตีความเป็น heading
- ลิงก์ใน nav ชี้ไฟล์ผิด/ไฟล์หาย → `--strict` ต้อง fail ไม่ใช่ปล่อยผ่าน
- หน้าไทยที่มีตาราง/โค้ดยาวต้องไม่ล้นจอบนมือถือ
- Pages ครั้งแรกอาจ 404 หลายนาที — ต้อง poll ไม่ใช่สรุปว่า fail

### Task 1: Extraction script + generated chapter files

**Files:**
- Create: `tools/extract_lessons.py`
- Create: `docs/opencode/01-architecture.md` … `07-cli-api.md`
- Create: `docs/linux/01-filesystem.md` `02-text-pipes.md` `03-permissions.md`
- Create: `docs/git/01-git-github.md`
- Read: `/tmp/opencode/session-export.json`

**Interfaces:**
- Produces: 11 Markdown files whose first line is `# <chapter title>`; script exits non-zero if any mapping is missing

- [ ] **Step 1: Define the mapping and write the extractor**

`tools/extract_lessons.py`:

```python
MAPPING = [
    ("# บทเรียน OpenCode (V2)", "docs/opencode/01-architecture.md"),
    ("# บทที่ 2: Configuration", "docs/opencode/02-configuration.md"),
    ("# บทที่ 3: Agents", "docs/opencode/03-agents.md"),
    ("# บทที่ 4: Commands", "docs/opencode/04-commands-skills.md"),
    ("# บทที่ 5: Permissions", "docs/opencode/05-permissions.md"),
    ("# บทที่ 6: MCP", "docs/opencode/06-mcp-plugins.md"),
    ("# บทที่ 7: CLI", "docs/opencode/07-cli-api.md"),
    ("# บทที่ 1: ระบบไฟล์", "docs/linux/01-filesystem.md"),
    ("# Linux บทที่ 2:", "docs/linux/02-text-pipes.md"),
    ("# Linux บทที่ 3:", "docs/linux/03-permissions.md"),
    ("# Git & GitHub บทที่ 1:", "docs/git/01-git-github.md"),
]
```

Behavior: load JSON, collect `content[].text` ของ message type `assistant`; สำหรับแต่ละ mapping หา part ที่มีบรรทัดขึ้นต้นด้วย marker (unique); slice ตั้งแต่บรรทัดนั้นถึงท้าย part; เขียนไฟล์

- [ ] **Step 2: Add structural validation inside the script**

หลังเขียนทุกไฟล์ ให้ assert:
- จำนวนไฟล์ที่เขียน = 11
- ทุกไฟล์เริ่มด้วย `# `
- จำนวนบรรทัดที่เป็น code fence (```` ``` ````) เป็นเลขคู่
- ไม่มี marker แชทในบรรทัดนอก fence: `มีครับ 👍`, `บอกได้เลยครับ`, `เดี๋ยวผม`

ถ้า assert fail → `sys.exit(1)` พร้อมชื่อไฟล์

- [ ] **Step 3: Run and verify**

Run: `python3 tools/extract_lessons.py`  
Expected: `wrote 11 files` และ exit 0

- [ ] **Step 4: Inspect headings and sizes**

Run: `for f in docs/*/*.md; do echo "$f $(wc -c < "$f")"; head -1 "$f"; done`  
Expected: 11 บรรทัด หัวข้อตรงกับ mapping, ทุกไฟล์ > 3 KB

- [ ] **Step 5: Commit**

```bash
git add tools/extract_lessons.py docs/
git commit -m "feat(docs): extract 11 lessons from session export"
```

## Amendments after review (2026-11-14)

The plan treated `check_docs.py` marker checks as sufficient validation. A fresh-context review proved otherwise: a wrong `chmod` answer, a wrong action count, a leaked chat section, and five mixed-script passages all passed. Amendments:

- **A content read-through is required**, not optional: automated checks catch structure and leakage, not correctness. The review read all 11 pages; the corrected facts are verified below.
- `check_docs.py` now also rejects: chat-only section headings (`## ก่อนไปบทถัดไป` …), `U+FFFD`, CJK/Cyrillic text outside code fences, and Thai/Latin run-together text (e.g. `ไฟล์ystem`).
- Transcript defects are corrected in `REPAIRS` inside `extract_lessons.py` with exact-match, one-occurrence assertions, so regeneration stays deterministic while the pages stay fixed.
- Corrections applied: `所以你ต้องตรวจเอง`→Thai, `主线`→`สายหลัก`, `причина`→`ต้นเหตุ`, `มี�ลายชั้น`→`มีหลายชั้น`, `ไฟล์ystem`→`ระบบไฟล์`; `chmod u-x,g+w,o-rwx,o-r,g+r`→`chmod u-x,g-x,o-rwx` (verified `751`→`640`); `7 actions`→`8 actions`; Linux 2 links to OpenCode ch.5; DB size and ch.6 MCP state marked as time-of-writing.
- `.gitignore` now covers `*.db-wal`, `*.db-shm`, `__pycache__/` (SQLite sidecars carry session data on a public repo).
- Workflow triggers on `tools/**` and uses `cancel-in-progress: false` so a Pages deploy is not cancelled mid-flight.
- Action majors were checked (checkout v7, setup-python v7, upload-pages-artifact v5, deploy-pages v5) but left at the locally verified majors; bump separately after a live deployment is green.

**Deferred (YAGNI):** the extractor's single-marker slicing and partial-write behavior only matters for a different transcript shape; this site is generated from one fixed export.
